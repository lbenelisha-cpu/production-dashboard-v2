# תיקון 502 — ניסיונות חוזרים ב-storage API

## הבאג

`index.html`, שורה 775 בגרסה המקורית:

```js
const attempts = action === 'get' || action === 'getMany' || action === 'status' ? 2 : 1;
```

לפעולות **`set`** ו-**`appendEvent`** הערך היה **1**.

מתחת, בלוק ה-catch כבר הכיל לוגיקת retry נכונה:

```js
const retryable = err?.name === 'AbortError' || [502,503,504].includes(Number(err?.status));
if(!retryable || attempt === attempts) throw err;
```

אבל עם `attempts = 1`, התנאי `attempt === attempts` מתקיים כבר בסיבוב הראשון.
**בלוק ה-retry היה קוד מת עבור כל פעולת כתיבה.**

העלאת קובץ האיכות הגדול מפורקת למאות קריאות `set`. Netlify Blobs מחזיר
502/503 חולפים תחת עומס — זה נורמלי. 502 בודד על מקטע אחד הפיל את כל
ההעלאה, ללא ניסיון שני.

זה מסביר למה זה נכשל דווקא על הקובץ הגדול: ככל שיש יותר מקטעים, הסיכוי
שלפחות אחד יקבל 502 שואף ל-1. בקבצים קטנים אותו באג פשוט לא מתבטא.

בצילום הרשת שלך: 2 קריאות `storage` ב-502, כל השאר 200.

## התיקון

1. **ניסיונות חוזרים לכל הפעולות** — `STORAGE_MAX_ATTEMPTS = 5`, כולל `set`.
2. **השהיה מעריכית עם jitter** — 500ms, 1s, 2s, 4s (תקרה 8s) ועוד 0-300ms
   אקראי. ה-jitter חשוב: בלעדיו מקטעים מקבילים מנסים שוב בו-זמנית ומחזירים
   בדיוק את העומס שגרם ל-502.
3. **הורחבה רשימת השגיאות החולפות** — נוספו 429 (rate limit), 500, וכשל רשת
   של `fetch` (נזרק כ-`TypeError`, שקודם לא נחשב ל-retryable).
4. **הודעת שגיאה שימושית** — אחרי מיצוי הניסיונות ההודעה כוללת את הפעולה,
   קוד הסטטוס ומפתח המקטע שנכשל, במקום "storage api error 502" גנרי.
